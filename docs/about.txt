# Project Name: AnimeEdu
## The AI-Powered Educational Learning Platform

### 1. What is this project?
AnimeEdu is an advanced, AI-powered platform designed to make learning incredibly fun, engaging, and interactive. Instead of reading boring textbooks, students can learn through anime-style scenes, interactive 3D models, hands-on HTML5 simulations, and multi-episode animated stories. It also features a real-time voice-chat AI tutor named "Bella". 

### 2. The Core Modules (What can it do?)
- **Scene Forge (The Artist):** You type a topic (like "Photosynthesis"), and it generates an educational anime-style image explaining it.
- **Lab Engine (The Scientist):** It builds interactive, playable HTML5 simulations (like mixing chemicals or seeing physics in action).
- **Holodeck (The 3D Printer):** Generates 3D models of real-world objects, like the human heart or a car engine, which you can rotate and zoom in on.
- **Chronicle (The Storyteller):** Creates multi-episode anime stories with voice narration and video to explain complex topics over time.
- **Bella (The Tutor):** An AI companion that floats on the screen. You can talk to her using your microphone, and she speaks back, answering any questions you have.

---

### 3. Our Technology Stack (What are we using?)

#### Frontend (The User Interface - What you see and click)
- **Next.js 14 & React:** The core framework used to build the website. It handles multiple pages, routing, and creating the buttons and layout.
- **TailwindCSS:** A styling tool we use to make the website look beautiful, colorful, and modern without writing endless CSS code.
- **TypeScript:** A strict version of JavaScript that catches errors before the code even runs, making the website very reliable.

#### Backend (The Engine - The hidden logic and database)
- **FastAPI (Python 3.11+):** The main server. It receives requests from the frontend (like "generate a 3D model"), processes them, and sends the result back. It is incredibly fast.
- **SQLAlchemy & app.db:** Our database system. It remembers user sessions, saved assets, and generated files.
- **Celery & Redis:** Our "background workers". Generating AI content takes time (sometimes minutes). Instead of freezing the website while waiting, the Backend hands the heavy task to Celery. Celery works on it in the background while the user continues browsing. Redis is the messenger that passes the task to Celery.

#### AI Services (The Brains - The intelligent helpers)
- **Groq (LLaMA 3.3 70B):** The main "thinking" brain. It creates the prompts, powers the Bella AI tutor, and acts as a safety filter to prevent bad words. Groq is famous for being incredibly fast at processing text.
- **Pollinations / Hugging Face:** Used for generating 2D images.
- **Tripo AI:** A specialized AI just for generating 3D models.
- **edge-tts & Whisper STT:** "TTS" means Text-to-Speech (making the AI talk). "STT" means Speech-to-Text (understanding your microphone voice).

### 4. Architecture & Working Flow (How does it all connect?)

Imagine you click the **"Generate 3D Model of a Heart"** button. Here is the step-by-step journey:

1. **The Click (Frontend):** You click the button in your browser (Next.js).
2. **The Request (API Call):** The Frontend sends a secure message to the Python Backend (FastAPI), asking for the model.
3. **Safety Check (Backend):** FastAPI asks Groq (the AI) to check if the request is safe and educational. If it's a bad request, it stops here.
4. **Task Delegation (Celery):** Because 3D models take 1-2 minutes to make, FastAPI tells the Frontend: "I'm working on it, here is a Job ID!" and hands the actual heavy lifting over to the background worker (Celery).
5. **Real-time Updates (WebSocket):** The Frontend connects to the Backend using a "WebSocket" (a live, open telephone line). It listens for updates using the Job ID.
6. **The AI Generation (Tripo AI):** The Celery worker contacts the external AI (Tripo AI), waits for the 3D model to be created, and downloads it.
7. **Saving (Database):** The worker saves the downloaded 3D model to our local storage and logs it in the SQLAlchemy database.
8. **The Notification (WebSocket):** The worker sends a message through the WebSocket: "The job is 100% complete!"
9. **The Display (Frontend):** The website sees the 100% message, stops the loading spinner, and displays the beautiful 3D heart on your screen.

---

### 5. Why did we choose this structure?
- **Separation of Concerns:** By keeping the Frontend (Next.js) and Backend (FastAPI) completely separate, we can update the website's look without breaking the AI logic, and vice versa.
- **Performance:** Python is the absolute best language for AI integrations, but Next.js is the absolute best for user interfaces. By using both, we get the best of both worlds.
- **Asynchronous Background Tasks:** Using Celery prevents the server from crashing when 50 people ask for 3D models at the exact same time. It creates an organized waiting line (queue).
- **Safety First:** The two-stage safety filter ensures that this educational tool remains appropriate for students of all ages.
